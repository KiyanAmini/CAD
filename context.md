# Section 1 Context: FP16 Fully Connected Neural-Network Accelerator

## 1. Objective

Design a synthesizable RTL accelerator for classifying one 28 x 28 grayscale MNIST image. The network is a fully connected neural network with this fixed topology:

```text
784 input pixels -> 8 neurons -> ReLU -> 10 neurons -> argmax digit
```

The accelerator must compute the same results as the supplied reference model in `assests.zip`, especially `test.py` in `MODE = "fp16"`. The predicted digit is the index of the largest final logit and is an integer from 0 through 9.

This document is the complete behavioral contract. Do not invent alternative dimensions, arithmetic modes, memory layouts, or handshake meanings.

## 2. RTL and arithmetic requirements

- Use synthesizable SystemVerilog-2012.
- Use a single synchronous clock named `clk` and a synchronous, active-high reset named `rst`.
- Use positive-edge triggered sequential logic.
- Use nonblocking assignments in clocked processes and blocking assignments only for combinational calculations or temporary variables.
- Do not use real numbers, floating-point software libraries, unsynthesizable delays, `initial` blocks for functional behavior, or vendor-specific floating-point primitives.
- All stored values, multiplier inputs/outputs, adder inputs/outputs, biases, activations, logits, and registered intermediate values are IEEE-754 binary16 (FP16), 16 bits wide.
- The implementation may contain exactly one reusable FP16 multiplier and one reusable FP16 adder. Do not replace the required sequential datapath with a large parallel array of multipliers or adders.
- Multiplication and addition are separate operations. Do not infer a fused multiply-add.
- Every multiply result is rounded to FP16 before it is added.
- Every add result is rounded to FP16 before it is stored or used by the next operation.
- The reference arithmetic is pure FP16 arithmetic; a hidden FP32 accumulator is not allowed.
- Inputs are finite FP16 values in the supplied data. IEEE-754 special values need not be generated by the design.

## 3. Network equations and exact operation order

Let `x[p]` be input pixel `p`, `0 <= p < 784`. Let `W1[n][p]` and `b1[n]` be first-layer weights and biases, `0 <= n < 8`. Let `W2[d][h]` and `b2[d]` be second-layer weights and biases, `0 <= d < 10`, `0 <= h < 8`.

For each first-layer neuron, initialize the FP16 accumulator to `b1[n]`, then process pixels in increasing index order. For each pixel, compute an FP16 product and immediately add it to the FP16 accumulator:

```text
acc = b1[n]
for p = 0 .. 783:
    product = FP16(W1[n][p] * x[p])
    acc     = FP16(acc + product)
fc1[n] = acc
```

Apply ReLU independently to each first-layer result:

```text
hidden[h] = 0.0              if fc1[h] < 0.0
hidden[h] = fc1[h]           otherwise
```

A negative zero is normalized to positive zero. The eight `hidden` values are the inputs to the second layer.

For each second-layer neuron, use the same ordered FP16 MAC procedure, with hidden index order 0 through 7:

```text
acc = b2[d]
for h = 0 .. 7:
    product = FP16(W2[d][h] * hidden[h])
    acc     = FP16(acc + product)
logit[d] = acc
```

The final prediction is the lowest index attaining the maximum FP16 logit. In normal supplied data there are no ties; if a tie occurs, retain the lowest digit index. Softmax is not part of the RTL and must not be computed.

## 4. Transaction-level behavior

The top-level accelerator shall provide `clk`, `rst`, a one-cycle `start` request, a one-cycle `done` indication, ten parallel 16-bit FP16 logits, and a 4-bit `prediction` output.

- While `rst` is high on a rising edge, all controller state, accumulators, valid flags, `done`, `prediction`, logits, and internal read/write pointers are reset. Reset values are zero unless a signal is purely an internal empty/full flag, in which case it is reset to its inactive state.
- A `start` request is accepted only while the accelerator is idle. A request received while busy is ignored.
- One accepted request processes exactly one 784-value image from the configured input memory and runs both network layers.
- `done` is low during processing and is asserted for exactly one clock cycle when all ten final logits and the prediction have been written.
- The ten logits and `prediction` remain stable after `done` until the next accepted `start` or reset.
- No new transaction may overlap an active transaction.
- The implementation may expose internal memories or a wrapper for simulation, but the datapath behavior and timing rules in this document must not change.

## 5. Input and parameter files

The supplied files are line-oriented hexadecimal FP16 bit patterns. Each nonempty line contains exactly four hexadecimal digits, with no `0x` prefix. Uppercase and lowercase hexadecimal are equivalent. A line is interpreted as the 16-bit IEEE-754 binary16 encoding, not as an integer or decimal number.

The files are:

- `test_image.mem`: exactly 784 values, in row-major image order. Value 0 is pixel `(row 0, column 0)` and value 783 is pixel `(row 27, column 27)`. Pixel values are normalized FP16 values.
- `fc1_weights.mem`: exactly 8 x 784 = 6272 values, flattened as `W1[n][p]` with neuron `n` as the outer index and pixel `p` as the inner index. Therefore the first 784 entries belong to neuron 0, the next 784 to neuron 1, and so on.
- `fc1_bias.mem`: exactly 8 values, where entry `n` is `b1[n]`.
- `fc2_weights.mem`: exactly 10 x 8 = 80 values, flattened as `W2[d][h]` with digit `d` as the outer index and hidden index `h` as the inner index.
- `fc2_bias.mem`: exactly 10 values, where entry `d` is `b2[d]`.

The provided Python reference reads the files with `reshape(8, 784)` and `reshape(10, 8)`. RTL indexing must produce the same logical matrices.

## 6. SRAM contract

Weights are read through an SRAM-like synchronous memory model rather than as a combinational bulk array.

- The SRAM address selects one row of 112 bits.
- One row contains seven consecutive FP16 values, in ascending logical weight order.
- After an address request is accepted, the corresponding row becomes valid exactly seven rising clock edges later.
- The seven FP16 values must be captured in seven registers so the multiplier can consume one value per cycle.
- Requests must preserve order. The design must not use a row before its seven-cycle latency has elapsed.
- First-layer weights occupy 896 complete rows (`6272 / 7`).
- Second-layer weights occupy 12 physical rows. The supplied `fc2_weights.mem` contains 80 values, so the final physical row contains three valid weights (lanes 0 through 2) and four padding positions (lanes 3 through 6). Padding positions must never contribute to a MAC.
- Because the second-layer file is flattened as `W2[d][h]` with eight values per digit while physical rows contain seven values, a physical row may cross a digit boundary. The controller must gather the logical per-digit groups explicitly: for `flat_index = 8*d + h`, use `row_addr = 896 + floor(flat_index/7)` and `row_lane = flat_index % 7`, then present each digit's hidden indices 0 through 6 followed by hidden index 7 to the multiplier.
- Biases and the 784 input pixels may be implemented as separate memories or register files, but their logical contents and index order are exactly those in Section 5.

## 7. Multiplier, ping-pong buffer, and accumulator behavior

The multiplier reads the seven captured FP16 weights and the corresponding seven FP16 input values. It produces one FP16 product per clock for seven clocks. Products are written sequentially into the currently selected write half of a two-half ping-pong buffer.

Each ping-pong half contains seven FP16 entries and independent write/read position tracking. At any time one half is being filled by the multiplier and the other half is being drained by the accumulator. A half may be swapped only after its seven required writes and the other half's valid reads are complete. Full/empty or equivalent valid/ready state must prevent overwriting unread products and reading unwritten products.

The accumulator consumes products in the same logical order as the reference MAC. Within a full seven-product group it performs a left fold:

```text
acc <- FP16(acc + product[0])
acc <- FP16(acc + product[1])
...
acc <- FP16(acc + product[6])
```

Groups are processed in increasing input-index order. First-layer neurons therefore process 112 groups of seven products. The second layer processes seven products followed by one final product; the unused six positions of the final group are invalid and are skipped, not added as fabricated data. The bias is loaded into the accumulator before the first product of that neuron, exactly as in the reference model.

Only after the final valid product of a neuron has been accumulated may the neuron result be marked valid. The first-layer result is then passed through ReLU. The second-layer result is stored as a final logit.

## 8. Layer sequencing and storage

The controller must complete all eight first-layer neurons before starting second-layer computation. The eight ReLU outputs must remain available for every one of the ten second-layer neurons; no hidden activation may be overwritten before the last second-layer neuron has consumed it.

The assignment permits a ten-entry FP16 register file for second-layer work: entries 0 through 7 hold the hidden activations, and entries 8 and 9 are initially unused. If final logits reuse those physical registers, writeback must be staged or otherwise arranged so that hidden values remain intact until all ten second-layer MACs are complete. This storage choice must not change the observable results.

After all ten logits are valid, compare them in digit-index order, select the lowest-index maximum, drive `prediction`, and pulse `done`.

## 9. Determinism and verification

The design must be deterministic. The fixed neuron order, input order, bias initialization, product-before-add rounding, group order, and tie-breaking rule above are mandatory. A correct simulation must match the supplied `test.py` golden model in pure-FP16 mode bit-for-bit for the ten logits and the predicted digit.

The testbench may inspect internal or wrapped memories, but it must be able to verify:

1. reset behavior;
2. acceptance of one `start` transaction;
3. SRAM seven-cycle latency;
4. correct FP16 products and ordered accumulation;
5. ReLU behavior;
6. all ten final logits;
7. the argmax prediction and one-cycle `done` pulse.

Do not silently substitute FP32 accumulation, a different weight ordering, a different bias placement, a different reduction tree, a different reset polarity, or a different interpretation of the memory files.
